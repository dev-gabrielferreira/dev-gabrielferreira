# 💫 Sobre mim

**Engenheiro de Dados em formação** — Python · SQL · Airflow · dbt · AWS · Kafka · Databricks

Passei os últimos anos do lado de onde os dados nascem: chão de fábrica, sensores, CLPs, sistemas supervisórios e centrais de energia. Como Engenheiro de Controle e Automação (UFOP), meu trabalho sempre foi extrair sinal de dado bruto — históricos de medidores, séries temporais de telemetria, eventos de alarme — para sustentar decisões de operação e manutenção.

Hoje estou levando essa experiência para o outro lado do fluxo: **construir os pipelines**. Curso pós-graduação em Engenharia de Dados na PUC Minas e desenvolvo em público um portfólio de pipelines com dados reais do setor elétrico brasileiro.

O que eu trago que é raro na área: entendo o domínio industrial por dentro. Sei o que um dado de sensor significa, por que ele chega sujo e qual decisão ele precisa sustentar.

## 🛤️ Trilha de portfólio — do sensor ao lakehouse

Uma sequência deliberada de projetos, cada um construindo sobre o anterior, usando dados abertos do sistema elétrico brasileiro (ONS/ANEEL) e telemetria industrial realista:

| # | Projeto | Foco | Status |
|---|---------|------|--------|
| 1 | [`energy-load-etl`](#) | ETL batch, validação de dados, Parquet, dashboard | 🚧 em desenvolvimento |
| 2 | [`maintenance-warehouse`](#) | Modelagem dimensional (star schema, SCD2), dbt, arquitetura medalhão | ⏳ planejado |
| 3 | [`aws-energy-datalake`](#) | Data lake em S3, DAGs no Airflow, Athena, agendado e monitorado | ⏳ planejado |
| 4 | [`iot-telemetry-streaming`](#) | Kafka, agregações em janelas, detecção de anomalias near real-time | ⏳ planejado |
| 5 | [`energy-lakehouse-databricks`](#) | PySpark, Delta Lake, jobs em escala no Databricks | ⏳ planejado |

Todo projeto entrega diagrama de arquitetura, ambiente reprodutível em um comando, verificações de qualidade de dados e uma seção **"o que aprendi"** — incluindo pelo menos uma falha real e como resolvi.
